# Q1081–Q1090 逐题审查

- Q1081: 控制器可批量一致配置，南向接口与设备交互；传统设备通常有分布式控制与逐台管理，但并非必然。北向接口面向应用。原答案图误配，已移除；原题图保留。
- Q1082: 原图显示五个匹配目标，现恢复 DELETE 槽并修正 PUT/POST/GET/PATCH 配对；原答案图的 PUT/PATCH 显示错误，已移除。HTTP PUT 通常请求创建或替换目标资源，POST 由目标资源按自身语义处理；GET 检索；DELETE 移除关联；PATCH 应用修改指令。具体接口行为与响应受实现决定，幂等不排除日志等副作用。
- Q1083: 控制器支持集中软件管理、开放接口和配置编排；传统逐台配置可处理控制器未覆盖的定制，但传统网络也能使用自动化，控制器也能支持自定义。答案图将编排和定制交换，已移除。
- Q1084: 配置管理维护期望配置状态，编排协调跨系统任务。Puppet 可用于配置管理；Ansible 可用于编排也可用于配置管理，因此此题描述限定工具使用场景，避免声称二者互斥。
- Q1085: 常见 Ansible 场景使用 YAML playbook 和 SSH，但也支持其他连接；Chef 配方采用 Ruby DSL，Push Jobs 的 10002 属特定组件端口，不能代表所有 Chef 通信；Puppet manifest 描述期望状态，8140 是典型 Puppet Server 端口。版本和部署可以不同。
- Q1086: POST 常用于由服务端处理创建；GET 检索；DELETE 请求移除 URI 的关联；PUT 请求用表示创建或替换目标资源。题干明确目标是完整替换，使 PUT 与 PATCH 的局部更改可区分；操作成功、持久存储和副作用依服务实现。
- Q1087: client-server 分离关注点；layered system 按层组织；cacheable 允许按缓存规则复用响应；stateless 不依赖服务器保存客户端会话上下文，但服务端可以保存资源状态；uniform interface 统一资源交互约束，不规定只能用 JSON。原答案图错配，已移除。
- Q1088: playbook 是 YAML 中组织 play 的任务集；control node 运行 Ansible，managed node 是被管理目标；task 调用模块，module 是执行具体工作的可重用单元，常用 Python 但不限定语言；inventory 可来自文件或动态来源。网络模块常在控制节点运行，托管主机也可安装 Ansible。原答案图对调控制与受管节点，已移除。
- Q1089: 传统逐台管理常需对每个设备分别执行变更；控制器可提供集中视图和管理。成本取决于规模、许可与运维，原题把成本较高视为必然不成立，已改为逐台软件操作的明确描述。原答案图所示原文字已失效，移除以免误导。
- Q1090: 接收灵敏度是规定误码条件下可解码所需的最低信号功率；噪声底是接收频带噪声功率；反射是波遇界面回弹；吸收是材料将部分射频能量转为热等形式；SNR 是信号与噪声的功率比。自由空间随距离的路径损耗并不是材料吸收。SNR 高低影响可用调制编码，但不保证固定吞吐。原答案图配对错误，已移除。
