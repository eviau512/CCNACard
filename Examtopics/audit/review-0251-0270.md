# Q251–Q270逐题审查

以下为人工初审历史；已直接查看11张原图。修订另见清单/回执，未按解释长度或关键词自动批准。

| 题号 | 原答案 | 初审 | 核验与修订 |
|---|---|---|---|
| 251 | B | 歧义 | 原题泛称减少多类型设备关联时间，未给客户端k/v能力，B与D对应不同优化环节，不能证明B唯一；解析把Disassociation Imminent说成保证全设备无缝漫游，并把D的真实功能排除。明确目标为已支持802.11k双频终端的扫描缩短/双频邻居报告，答案改D；解释v到期可断连而非通用保证。 [S1][S2] |
| 252 | D | 问题 | D/Friendly方向正确，但解析保证所有Syslog/SNMP报警绝对停止，未区分Friendly的Alert/Internal/External及通知策略。明确AireOS已确认的内部合法AP，Friendly/Internal；不能把所有未纳管设备一概判恶意，也不应为停止误报启用containment。 [S3] |
| 253 | C | 问题 | C正确，但未开LAG并非所有逻辑接口完全不能备端口；AireOS动态接口可有primary/secondary。解析还保证毫秒级无损、单流带宽无限增加，均非LAG必然性质。改为成员冗余与聚合吞吐、哈希分流，区别SSO及加密。 [S4] |
| 254 | D | 问题 | 经典AireOS分离接口流程中Discovery Request先到management，随后向响应通告的AP-manager发送Join Request；原题指定AP-manager却无Join Request选项，D的解释将两接口混为一谈。题干改为management上的发现请求，保留D，并解释可合并接口但不能混用阶段。 [S5] |
| 255 | C | 问题 | 已看GUI：服务器Enabled，Network User/Management未选，C为全局网络认证用途选择。但官方说明WLAN显式指定AAA服务器可不勾全局Network User，原解析“绝不会”错误。题干补未在WLAN单独选服务器、使用全局列表；C保留并明确例外。 [S6] |
| 256 | C | 通过 | C/Allow AAA Override正确，对应依据RADIUS身份授权覆盖WLAN默认VLAN。解析列64=13、65=6、81组标识并区分LAG、RRM和MIC AP授权，足以解释选项；ISE采用AD是工作流例，不将其当所有部署的强制依赖。完整部署仍需RADIUS/目标VLAN可用。 [S7] |
| 257 | A | 通过 | 已看路由表：D /27 [90/2888597172]、O /19 [110/292094]、R /24 [120/2]均包含172.16.32.1，/27最长，下一跳20.1.1.1。A正确，AD入表与跨协议metric不能直接比的区分成立。独立地址计算另留证据。 |
| 258 | C | 问题 | 已看三路由器和RIB：R1仅直连10.10.10/24，R3已具返回10.10.10/24的静态路由，C补R1前往20.20.20/24 via10.10.10.2正确。但末尾声称静态下一跳必须直连、跨跳不能成立，忽略可递归解析下一跳。重写为本图邻接R2最直接，保留递归机制限定。 [S8] |
| 259 | A | 问题 | A/默认带宽+延迟正确，但解析将MTU列入度量参数、通式分母括号错误且LaTeX的left已损成≤ft。删错误通式，给经典默认K值、明确带宽最小/延迟累加与单位，纯文本公式保留，MTU与hop count不计复合度量。 [S9] |
| 260 | C | 问题 | C默认路由正确，但四组CLI源全压成一行，需恢复模式/命令分行。补192.168.1.1可解析且转发开启的前提，区别default-gateway；模板参数全局renderer已保护，不把已修问题再算当前丢失。 [S8] |
| 261 | B | 问题 | B和四项范围计算正确，但解析把FIB/RIB一并称硬件转发表，混淆控制平面的路由信息库与数据平面转发表。改为在已安装有效路由中做最长匹配，并明确RIB/FIB角色；仍保留B及四个完整单行ip route。 |
| 262 | D | 通过 | 已看图三条前缀：EIGRP /24和RIP /27包含192.168.12.16，OSPF .0/28只到.15。选D/RIP；解析明确先匹配再比长度，不能按最小AD或三个不同前缀ECMP。 |
| 263 | B | 问题 | 已看四条show ip route：i L1写192.168.10.0/13带host bits，不是IOS规范网络前缀，解释照抄。改编为规范192.168.0.0/13并重绘完整路由表，仍覆盖目标.10.16且RIP /27最长，B不变。不要将原错误行当真实IOS规范输出。 |
| 264 | B | 问题 | 已看图，.165命中OSPF .160/29 via10.10.10.5 Gi0/1，对应Router3，B正确。图同时有S*默认，原解析“唯一匹配”需区分更明细与默认：默认也匹配，只因/29更长而落选。改写逐项范围和出接口证据。 |
| 265 | C | 问题 | C/同10.10.10.0/24跨协议比AD正确。解析称Cost为OSPF私有、把OSPF DR RID与下一跳IP大小混用，均非准确术语。重写只比较同前缀AD，其他前缀不靠短掩码入表，平局/有效性不虚构。 [S10] |
| 266 | B | 问题 | 已看R1/SW1/SW2：B子接口+dot1q20正确，但CLI源全部压平且B/C提示符错误应config-subif。图SW1 E0/1仅allowed vlan10，若声称配置后VLAN20端到端畅通则错误。明确仅补R1本地子接口，列出后续trunk需放行20；物理口多IP并非协议绝对禁止。 [S11] |
| 267 | C | 问题 | 已看brief：Loopback0=172.16.15.10 up/up，192.168.0.1是Gi1/0而非loopback。C在首次自动选择时正确，但仅brief不足以排除手工RID/旧运行RID，原解析只有模板。补新启OSPF且无router-id、接口均已存在，按具体接口逐项解释并说明不自动抢占。 [S12] |
| 268 | C | 问题 | 已看配置：Router1 hello5，Router2默认Ethernet hello10，C正确。原解析凭hello5断言dead自动变20、又把MTU列成Hello内匹配参数；应只用已证明Hello不等，Dead独立核验，MTU属后续数据库交换。process1000/1001本地有效，RID1.1.1.1/2.2.2.2应不同。 [S13] |
| 269 | D | 问题 | 已看B*0/0 [20/0] via10.10.10.18，D正确，确为默认非静态。解析一处将network route写/1–/30、结尾写/1–/31自相矛盾，/31可为网络前缀。统一分类、默认只兜底不保证全部Internet无条件走默认。 |
